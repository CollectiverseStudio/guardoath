Checks on this record

Every check is one row of the table below, grouped by category, with two settings: Input (the user’s message) and Output (the AI’s answer). Each is a field on the tenant record, so a check can block on input and only flag on output, or run on one stage only. Select What is this? under a check for what it looks for and why you would use it, and Show rules to see the rules inside it, each with its own Input and Output setting. A rule uses its check’s setting (Same as check) until you give it its own, so you can block Personal data and allow only Email address. Type part of a rule name (for example email or IP address) or filter by category or setting to find a rule. Each rule shows its use case, an example it reports and a look-alike it does not. Changes apply from the next check. Every check request runs exactly these settings: there are no profiles to choose.

Off
The check does not run.
Block
A finding stops the message or answer.
Flag
A finding is reported and marked for review, and the message or answer still goes through. Only Block stops it.
Allow
A finding is reported, and the message or answer goes through.
Redact
Personal data only: what is found is replaced, the checks run again on the result, and the cleaned text goes through.

CSV / TSV attachments: automatic inspection

These saved settings apply only when actual file bytes arrive. Auto runs CSV and TSV formula inspection with the configured per-stage check and rule actions; Off marks a recognized CSV or TSV file as not inspected, not passed. Unsupported files are always held. An ordinary text-only request is unchanged.

API keys

Your application sends one of these keys with every check. You can have 2, so a key can be replaced without downtime. A new key is shown once; only its hash is stored.
