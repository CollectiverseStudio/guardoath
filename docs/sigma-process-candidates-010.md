# Staged process-creation batch010

immutable revision `05d1031f537e830b76da53bae2400c5814c89165`. This is source
screening and authored matching evidence, separate from default adoption.
The current catalog stays at **203 pinned rules /213 required source assets**.
No runtime, packaging, tenant, engine, registry or hosted behavior changes.

The candidate JSON retains every original ID, author, path, metadata field and
detection selector. The 25 YAML snapshots match the upstream Git objects byte
for byte. SHA256 and typed Git blob IDs identify each source. The original
Detection Rule License 1.1 is retained in the Sigma source directory.
The selection includes Java/SysAid parents, Kerberos coercion strings, selected
LOLBin command patterns, LSASS clones and MFTrace children. These are structured
Windows event detections, not generic chat-text checks.

Only unchanged single-mapping `selection` conditions using literal contains,
contains-all and suffix matching were admitted. Six inspected regex originals
are explicitly recorded as excluded in `batch_010_review.json`; no regex,
wildcard or unsupported construct was approximated. Remaining unscreened
upstream rules are not implicitly accepted or rejected by this batch.

There are 25 synthetic positive/benign pairs and 47 additional original
alternatives or all-term near misses. For example, devtoolslauncher.exe with
`LaunchForDeploy` matches its original rule; an ordinary executable does not.
Each event has explicit exact findings against all **228 proposed definitions**.
The reviewed candidate positives each match their target alone, and the primary
benign events match none. All 406 prior primary fixtures have explicit review
of new matches; none gain a new match. These observations apply only to the
frozen authored strings, not to every possible real event or global benignness.

nested fields, case-insensitive values, source exclusion and finding provenance
are tested. Commands are strings only and are never executed.

Use only explicit trusted host source `windows/process_creation` and configured
original rule IDs. The proposed metadata inventory selects **103 process /125
script rules**, retaining the **128-selected-rule maximum** and one inherited
per-event budget. Passing all228 directly rejects; no chunking, resetting or
silent truncation is allowed. Metadata `definition` remains source documentation,
not an extra trusted routing key or an authorization setting.
